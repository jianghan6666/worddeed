Try the synthetic demo.

The demo uses invented topics, model replies and scores to show how the coordinator connects stages, saves artifacts and reuses completed work. It requires Python 3.11 or newer and the standard library. It makes no AI calls and performs no empirical model fitting or Stata estimation.

From the repository root, choose a new output directory for the first run:

python3 -m agent_system.empirical.demo --out .local/connected-demo
python3 -m agent_system.empirical.demo --out .local/connected-demo --resume

Inspect summary.json, workflow/state.json and workflow/events.jsonl in that directory. They show what was produced, how stages connect and which work was reused on resume. The demo’s numerical values are invented examples.

Choose what to repeat.

The software demo, archived judgments and empirical study answer different reproducibility questions.

Saved judgments

Recalculate topic selections from archived reader records and inspect their reasons and disagreements. This route works without obtaining new AI judgments.

Empirical fitting

The recorded connected run reused saved representations and judgments, refitted Ridge and XGBoost, rebuilt financial inputs and estimated the original 25 dividend models. It used a Windows analysis environment and a separate Stata stage. Check the package’s prerequisites before attempting a new run; the saved receipt documents the earlier execution.

Fresh AI screening

The newer API adapter is implemented, but the released archive lacks 21 required inputs. Its input check fails before any model call. The current release alone is not sufficient for this route. Complete authorized inputs and provider access are needed before new screening can be tested.

The recorded empirical chain does not retrain the topic model, regenerate sentiment or obtain fresh reader votes. It also excludes the final appendix’s additional narrative-controlled models and proxy correlations. None of these computational routes alone validates the underlying construct.

Other microfoundational features

  1. Define the microfoundational feature. State which topics constitute evidence about the focal feature rather than about the contextual specificities facing a firm.
  2. Choose the behavioral and narrative cues. Identify appropriate sources, including their timing and possible common causes.
  3. Record the measurement choices. Record the corpus, prompts, requested and observed model information, judgments, aggregation rules and held-out groups.
  4. Specify tests in advance. Include independent criteria, competing measurements and a separate empirical question. Plan how alternative judgments will be compared.

The prototype connects the stages for one application. Work with other microfoundational features and different sources of behavioral and narrative cues still needs compatible inputs, justified statistical specifications and validation.

How the explanation handles differences between sources

The proposal presents the intended measurement design. The appendix and code specify what the CEO application delivered. The explanation distinguishes reader agreement from accuracy, the predicted score from its residual, and empirical association from construct validity.

The proposal’s broader diagram includes controls and fixed effects and calls the residual “decoupling.” The delivered CEO prediction mapping omits those controls, and the appendix requires separate evidence for a residual interpretation. The website uses its own explanatory visual; it does not reproduce or revise the submitted figure.

Check version differences against the sources supplied to you, including whether a claim describes a reported result, an implemented feature, a recorded run or proposed work.

The project responds to the Organization Science call for new measurement and reusable research infrastructure. Its contribution is a workflow whose judgments, predictions and empirical tests can be examined together.
